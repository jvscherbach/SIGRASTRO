# Hooks: as guardas do projeto (S6, bloco 6)

Os hooks do Claude Code rodam um comando antes (`PreToolUse`) ou depois (`PostToolUse`) de cada uso de ferramenta. O comando recebe o JSON do evento pela entrada padrão. **Código 2 bloqueia** (no `PreToolUse` a ação não acontece; no `PostToolUse` a mensagem volta ao Claude, porque a gravação já aconteceu) e devolve o `stderr` ao Claude; **outro código diferente de zero é erro não bloqueante** (a ação segue e um aviso aparece). Formato conferido na documentação oficial (`code.claude.com/docs/en/hooks`) para o Claude Code 2.1.

## Configuração

Em [`.claude/settings.json`](../../.claude/settings.json), versionado:

| Evento | `matcher` | Guarda |
|---|---|---|
| `PreToolUse` | `Bash\|PowerShell` | `guarda-bash.mjs` |
| `PreToolUse` | `Read\|Edit\|Write\|MultiEdit\|NotebookEdit\|Grep\|Glob` | `guarda-arquivos.mjs` |
| `PostToolUse` | `Write\|Edit\|MultiEdit` | `varrer-dados.mjs` |

O comando é sempre `node "$CLAUDE_PROJECT_DIR/.claude/hooks/<arquivo>.mjs"`, que funciona de qualquer diretório. **Windows:** os hooks rodam pelo Git Bash quando ele está instalado (o caso desta máquina). Sem Git Bash o Claude Code usa o PowerShell, onde `$CLAUDE_PROJECT_DIR` não é a variável de ambiente: a guarda não acharia o arquivo, sairia com erro **não bloqueante** e ficaria desligada (o aviso aparece). O `matcher` inclui `PowerShell` porque no Windows o Claude Code tem as duas ferramentas de shell.

**Reforço em `permissions.deny`** (vale mesmo com os hooks desligados; revisto na S6.1, bloco 2): `Bash(git commit:*)`, `Bash(git push:*)`, `Bash(gh:*)`, as mesmas três para `PowerShell(...)`, e `Read`/`Edit` de `.env`, `.env.local`, `.env.*` com as negações `!.env.example` e `!.env.*.example` logo depois (a documentação aceita negação `!` dentro do `deny`, na mesma fonte; uma regra `allow` não abriria exceção num `deny`), `mapa-local.csv`, `.secrets/**`, `.rastro/**`, `~/.rastro/**` e as credenciais do usuário (`~/.ssh/**`, `~/.aws/**`, `~/.gnupg/**`, `~/.kube/**`, `~/.docker/config.json`, `~/.git-credentials`, `~/.netrc`, `~/.npmrc`, `~/.claude/.credentials.json`). Nome solto vale em qualquer profundidade (formato do `.gitignore`). `Edit` cobre Write e NotebookEdit; o `Read` deny também vale para Grep, Glob e `cat`/`head`/`tail`/`sed`/`tee` no Bash. A documentação avisa que regra de `Bash` casa só o texto do comando (`git -C . push` escapa dela), por isso as guardas fazem a análise de verdade. As camadas, o que cada uma cobre e o sandbox (indisponível no Windows nativo) estão em [segredos.md](segredos.md).

## Guarda 1: `guarda-bash` (Bash e PowerShell)

**Postura (S6.1, D81): na dúvida, bloqueia.** Um comando que **pode** ler ou imprimir segredo e que a análise estática não consegue provar inofensivo é bloqueado, com a regra e o jeito permitido. Falso bloqueio é preferível a vazamento. A guarda é uma camada; as outras ficam em `docs/claude-code/segredos.md` (S6.1, bloco 2).

**Como lê o comando.** Divide em trechos (`&&`, `||`, `;`, `|`, `&`, quebra de linha, parênteses, chaves, `$( )` e crases, inclusive dentro de aspas duplas) e sabe quais vêm depois de um cano. Cada palavra é lida sem as aspas e com duas marcas: **expande** (há `$NOME`, `${..}`, `$(..)`, crase ou `%NOME%` fora de aspas simples: o valor só existe na execução; `$` no fim ou antes de aspa, como em `"fim$"`, é literal) e **curinga** (`*`, `?`, `[` fora de aspas). Decodifica `$'..'` (ANSI-C), junta pedaços com aspas (`'.env'.local`), considera a versão sem barra invertida (`.env\.local`) e expande chaves simples (`.e{nv,xx}.local`). Heredoc (`<<FIM`, `<<'FIM'`) e here-string (`<<<`, `@' '@`, `@" "@`) são tratados como **código** quando vão para shell ou interpretador e como **dado** nos demais (com a checagem de variável quando o documento expande). O programa de verdade é achado depois de atribuições, palavras de controle (`if`, `for`, `!`...) e invólucros (`sudo`, `env X=y`, `nohup`, `timeout`, `xargs`, `parallel`, `&` do PowerShell). Para busca e cópia recursiva, **confere no disco** se o alvo contém arquivo de segredo (sem seguir link de pasta; acima de 40 mil entradas, trata como "contém").

## Guarda 2: `guarda-arquivos` (Read, Edit, Write, MultiEdit, NotebookEdit, Grep, Glob)

Bloqueia quando `file_path`, `notebook_path`, `path`, `pattern` (no Glob) ou `glob` (no Grep) apontam para arquivo de segredo: `.env`, `.env.local`, `.env.<x>` que não termine em `.example`, um curinga que o alcance, `mapa-local.csv`, `.secrets/`, `/run/secrets*`, a pasta `.rastro` (segredos fora do projeto, [segredos.md](segredos.md)) e credenciais do usuário (`~/.ssh/`, `~/.aws/`, `.git-credentials`, `.npmrc`, `~/.claude/.credentials.json`...), com alternativas de glob (`{a,.env.local}`). No Grep o `pattern` é o texto procurado, não um caminho: buscar a palavra ".env.local" nos docs passa. `.env.local.example` e `.env.example` passam.

**Caminho normalizado (S6.1, bloco 2):** antes de conferir, o caminho é resolvido a partir da pasta da sessão (`cwd` do hook): `..`, `./`, barras invertidas, `~`, maiúsculas (a conferência ignora caixa), caminho POSIX do Windows (`/c/...`, `//c/...`) e o **destino real de link simbólico** (`realpath`: um `inocente.txt` que aponta para o `.env.local` é bloqueado; no Windows sem privilégio de link o teste é pulado e roda no CI Linux).

**Grep e Glob sobre pasta (S6.1, bloco 2; prova em [segredos.md](segredos.md)):** o **Grep** respeita o `.gitignore` e alcança arquivos ocultos não ignorados. Sem `glob`, só passa se **todo** segredo dentro da pasta estiver ignorado pelo `.gitignore` da raiz (conferido no disco, sem entrar em pasta ignorada e sem seguir link de pasta; padrões com `!`, barra final, `**`); com `glob` que não alcança segredo (`**/*.java`), passa; com `glob` que alcança (`**/.*`, `*`), bloqueia. O **Glob** não respeita o `.gitignore` (lista nomes ignorados): padrão que alcança nome de segredo (`**/*`, `**/.*`, `.e*`, `**/mapa-*.csv`) bloqueia; os demais passam. No projeto, Grep na raiz sem `glob` passa (todos os segredos estão no `.gitignore`); se alguém tirar um padrão do `.gitignore`, a mesma busca passa a bloquear.

Mensagens: a de segredo (`REGRA`) e, para busca sobre pasta, `REGRA_PASTA` ("Restrinja a pasta ou o padrão, ex.: Grep com `path: \"api/src\"` ou `glob: \"**/*.java\"`; Glob com `pattern: \"docs/**/*.md\"`").

## Guarda 3: `varrer-dados` (depois de Write, Edit, MultiEdit)

Lê o arquivo gravado (até 2 MB; ignora binários, `node_modules`, `dist`, `target`, `.git`, `.angular` e a própria `.claude/hooks/`) e procura, linha a linha:

- **CPF e CNPJ com dígito verificador válido**, com e sem máscara (11 ou 14 dígitos seguidos, também dentro de nome de arquivo, mas não no meio de um hash);
- **token**: JWT (`eyJ...` em três partes) e `Bearer` seguido de valor com cara de aleatório (24+ caracteres, com letra e dígito: "Bearer token-que-nao-existe" passa);
- **chave privada** (`-----BEGIN ... PRIVATE KEY-----`).

Achado: código 2 com a lista `arquivo:linha (tipo)`, **sem repetir o valor**, e a orientação: trocar por `<CPF_DE_TESTE>`/`<CNPJ_DE_TESTE>` ou por dado evidentemente fictício, e, em teste, gerar o valor por cálculo na hora.

**Fictícios aceitos** (lista `FICTICIOS` em `varrer-dados.mjs`): o CNPJ de exemplo do projeto `12.345.678/0001-90`, todo CPF/CNPJ inválido de propósito (como `000.000.000-01`, que nem passa no dígito verificador) e três números **didáticos clássicos, válidos por cálculo**, que os testes de validação e máscara já usavam antes desta guarda: `111.444.777-35`, `11.222.333/0001-81` e `123.456.789-09`. Para acrescentar outro, edite a lista e registre aqui; prefira sempre gerar o número no teste.

Na criação desta guarda a varredura de todos os arquivos do projeto achou só um JWT de exemplo escrito como literal num teste (`EventoDeAuditoriaTest`), que passou a ser montado na hora.

## Script `commit-bloco` (A1, bloco 1): o único caminho de commit automático

[`.claude/scripts/commit-bloco.mjs`](../../.claude/scripts/commit-bloco.mjs) (Node, sem dependência) é a **trava** do modo automático da A1: o agente `commitador` só roda este comando, e nenhum outro caminho de commit existe para os agentes. Chamada **exata**:

```
node .claude/scripts/commit-bloco.mjs --bloco <N> --mensagem .claude/tmp/commit-msg.txt
```

O Git é chamado por `execFile` com vetor de argumentos (nunca shell, nunca texto interpolado em comando). Na primeira verificação que falhar, o script sai com **código 2** e a mensagem `[commit-bloco] recusado na verificação <n>: ...`, **sem alterar nada** (nem o índice). Falha do próprio Git depois das verificações (gancho de commit recusou, índice travado) sai com código 1 e só o `stderr` do Git.

| # | Verificação | Recusa quando |
|---|---|---|
| 1 | **Argumentos** | não forem exatamente `--bloco <1 a 999, sem zero à esquerda> --mensagem .claude/tmp/commit-msg.txt`, nessa ordem (argumento extra, `--bloco=3`, `./`, `..`, barra invertida, outro caminho) |
| 2 | **Repositório e branch** | a pasta atual não é a raiz do repositório; a branch não começa com `auto/` (`main`, `master`, qualquer outra); HEAD solto; branch sem nenhum commit. A branch `auto/<nome>` é criada **pelo responsável** |

## Falha segura

Erro **interno** de qualquer guarda (JSON inválido, entrada sem o campo esperado, arquivo que sumiu, exceção) não bloqueia: escreve em `stderr` `[<guarda>] aviso: <motivo>; a ação segue sem esta guarda.` e sai com código **1** (não bloqueante). O motivo é só o tipo do erro, nunca o conteúdo da entrada. Só o que casa com uma regra sai com código 2. Cada guarda tem `timeout` de 10 a 15 s no `settings.json`; estourar o tempo também não bloqueia.
